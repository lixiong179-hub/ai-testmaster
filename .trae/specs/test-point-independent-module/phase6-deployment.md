# Phase 6: 部署与收尾（2个任务）

---

## T6.1: 部署上线（包含数据库迁移）

| 属性 | 内容 |
|------|------|
| **优先级** | 🔴 高 |
| **负责人** | 全栈开发/运维 |
| **预计工时** | 0.5 小时 |
| **依赖关系** | T5.1-T5.3 |
| **时间节点** | Phase6 第1个任务 |

---

### 目标描述

将代码部署到生产环境，包含数据库迁移操作，确保平滑上线。

---

### 具体实施步骤

1. **部署前检查清单**
   - [ ] 所有代码已合并到主分支
   - [ ] Git仓库状态干净，无未提交修改
   - [ ] 所有单元测试通过
   - [ ] 所有E2E测试通过（如有）
   - [ ] 数据库备份已完成并验证可恢复
   - [ ] 部署时间选择在低峰期（建议：凌晨或周末）
   - [ ] 回滚方案已准备就绪

2. **后端部署**
   - 拉取最新代码到生产环境
   - 安装/更新依赖（如有新增依赖）
   - 执行数据库迁移：`alembic upgrade head`
   - 重启后端服务
   - 验证后端健康检查接口正常响应
   - 验证API端点正常工作

3. **前端部署**
   - 构建生产版本：`cd src && npm run build`
   - 部署构建产物到Web服务器
   - 验证前端页面正常加载
   - 清除CDN缓存（如有）

4. **部署后冒烟测试**
   - 登录系统
   - 访问测试点管理页面
   - 验证列表正常显示
   - 验证新增/编辑功能正常
   - 验证生成用例功能正常
   - 验证其他原有页面功能正常

5. **监控**
   - 监控错误日志
   - 监控数据库性能
   - 监控API响应时间
   - 持续监控至少30分钟

---

### 回滚方案

如果出现严重问题，按以下步骤回滚：

1. **数据库回滚**
   ```bash
   alembic downgrade -1
   ```

2. **代码回滚**
   - 回滚到上一个稳定版本：`git reset --hard <commit-hash>`
   - 重新部署

3. **恢复验证**
   - 验证数据库正常
   - 验证服务正常
   - 验证功能正常
