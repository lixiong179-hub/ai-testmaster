# 测试用例生成模块重构 - 产品需求文档

## Overview
- **Summary**: 重构现有的测试用例生成模块，解决测试用例偏离实际项目需求、无法执行手工测试、与项目整体流程脱节等问题，建立从需求文档到测试点提取再到测试用例生成的完整链路。
- **Purpose**: 提高AI生成测试用例的质量和实用性，确保生成的测试用例能够真正执行，并且与项目的需求管理、测试点提取、测试任务执行等模块完全串联起来。
- **Target Users**: 测试工程师、QA人员、开发人员

## Goals
- 重构AI生成测试用例前端页面，支持从项目、需求文件、测试点完整流程生成测试用例
- 改进后端API，支持基于测试点批量生成测试用例
- 优化AI提示词，生成更具体、可执行的测试用例
- 实现完整的端到端流程：需求文档 → 测试点提取 → 测试用例生成 → 测试用例管理
- 确保生成的测试用例能够支持手工测试和后续的AI自动化测试

## Non-Goals (Out of Scope)
- 不重新实现需求文档上传功能（已存在）
- 不重新实现测试点提取功能（已存在）
- 不修改测试执行引擎
- 不实现全新的测试用例格式

## Background & Context
当前测试用例生成模块存在以下问题：
1. 前端页面仍为简单的"输入测试场景生成用例"模式
2. 生成的测试用例过于抽象，无法实际执行手工测试
3. 测试用例生成与项目需求管理、测试点提取等模块脱节
4. 缺乏批量生成和批量保存功能
5. 测试用例格式不统一，与后续自动化测试不兼容

## Functional Requirements
- **FR-1**: 重构AI生成测试用例前端页面，显示完整的项目-需求-测试点流程
- **FR-2**: 支持选择项目、需求文件、测试点来生成测试用例
- **FR-3**: 支持基于测试点批量生成测试用例
- **FR-4**: 支持批量保存测试用例到项目
- **FR-5**: 提供测试用例预览和编辑功能
- **FR-6**: 改进后端API，支持关联项目、需求文件、测试点信息
- **FR-7**: 优化AI提示词，生成包含详细操作步骤的可执行测试用例

## Non-Functional Requirements
- **NFR-1**: 测试用例生成响应时间≤5秒/用例
- **NFR-2**: 前端页面加载时间≤2秒
- **NFR-3**: 支持批量生成≥10个测试用例
- **NFR-4**: 生成的测试用例可编辑率达到100%
- **NFR-5**: 与现有数据库结构兼容

## Constraints
- **Technical**: 必须使用Vue3+TypeScript前端，FastAPI后端，DeepSeek AI模型
- **Business**: 必须遵循现有的项目结构和代码规范
- **Dependencies**: 依赖现有的需求管理、测试点提取、项目管理等模块

## Assumptions
- DeepSeek API能够正常调用
- 项目有有效的需求文档和测试点数据
- 用户已登录并有相应的项目权限

## Acceptance Criteria

### AC-1: 前端页面显示完整流程
- **Given**: 用户登录系统并进入AI生成测试用例页面
- **When**: 页面加载完成
- **Then**: 页面显示项目选择、需求文件选择、测试点选择三个步骤，形成完整的生成流程
- **Verification**: `programmatic`

### AC-2: 选择项目后加载需求文件
- **Given**: 用户在AI生成测试用例页面
- **When**: 用户选择一个项目
- **Then**: 系统自动加载该项目下的所有需求文件
- **Verification**: `programmatic`

### AC-3: 选择需求文件后显示测试点
- **Given**: 用户已选择项目和需求文件
- **When**: 用户选择一个需求文件
- **Then**: 系统显示该需求文件提取的所有测试点
- **Verification**: `programmatic`

### AC-4: 支持选择多个测试点批量生成
- **Given**: 用户已选择项目、需求文件和多个测试点
- **When**: 用户点击"批量生成"按钮
- **Then**: 系统为每个选中的测试点生成对应的测试用例
- **Verification**: `programmatic`

### AC-5: 生成的测试用例包含详细可执行步骤
- **Given**: 用户选择测试点并生成测试用例
- **When**: 测试用例生成完成
- **Then**: 测试用例包含详细的前置条件、操作步骤（含具体操作描述）、预期结果
- **Verification**: `human-judgment`

### AC-6: 支持测试用例预览和编辑
- **Given**: 测试用例已生成
- **When**: 用户查看生成结果
- **Then**: 用户可以预览所有生成的测试用例，并对任意用例进行编辑
- **Verification**: `programmatic`

### AC-7: 支持批量保存测试用例
- **Given**: 用户已生成并审核测试用例
- **When**: 用户点击"批量保存"按钮
- **Then**: 所有测试用例被保存到对应的项目中
- **Verification**: `programmatic`

### AC-8: 完整流程串联验证
- **Given**: 用户有一个包含需求文件的项目
- **When**: 用户执行完整流程：上传需求 → 提取测试点 → 生成测试用例 → 保存用例 → 查看用例列表
- **Then**: 整个流程完整可执行，生成的测试用例在项目用例列表中可见
- **Verification**: `programmatic`
