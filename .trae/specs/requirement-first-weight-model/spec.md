# 需求文档优先的AI测试用例生成权重模型 Spec

## Why

当前AI生成测试用例时，三者（需求文档/UI原型图/测试点）均等权重(各1/3)，导致生成的用例**严重偏离需求文档**，不可用。用户核心诉求：**生成的测试用例必须贴合需求文档，不偏离需求文档想要实现的效果。**

## What Changes

* 重构 `generate_test_case_enhanced()` 的 prompt 权重模型，从"均等权重"改为"需求文档优先"

* 新增 `_build_weight_model()` 函数，根据可用数据源动态计算权重描述

* 修改约束条款：需求文档是唯一"功能来源"，UI和测试点只能用于细化和验证

## Impact

* Affected code: `app/utils/ai_client.py` (prompt 生成逻辑)

* Affected code: `app/api/v1/endpoints/test_case.py` (UI 解析逻辑保持不变)

* 测试文件: `tests/services/test_case_edit_features.py` (新增权重模型单元测试)

## ADDED Requirements

### Requirement: 需求文档优先权重模型

系统 SHALL 根据可用数据源数量，按以下权重策略生成 AI prompt：

#### 场景1: 三者齐全（需求+UI+测试点）

* **需求文档 60%**（核心真理 — 定义"做什么"）：必须逐条覆盖需求中每个功能点，每项功能至少对应一个测试用例

* **测试点 25%**（生成范围 — 定义"测哪些"）：从需求的每个功能中选取对应的测试点，不能超出需求边界

* **UI原型图 15%**（验收标准 — 定义"怎么验"）：验证步骤中的操作对象与UI元素一致

#### 场景2: 需求 + UI（无测试点）

* **需求文档 75%**：核心依据，覆盖所有功能点

* **UI原型图 25%**：验收标准

#### 场景3: 需求 + 测试点（无UI）

* **需求文档 70%**：核心依据，覆盖所有功能点

* **测试点 30%**：定义生成范围

#### 场景4: 仅需求文档

* **需求文档 100%**：唯一依据，逐条覆盖每个功能点

#### 场景5: 仅UI / 仅测试点 / 其他组合（无需求）

* 以可用数据源为100%，但提示"缺少需求文档可能导致用例偏离实际功能"

### Requirement: 防偏离约束

系统 SHALL 在 prompt 约束条款中加入以下硬性规则：

1. **功能边界守则**: 用例中的每一步操作必须在需求文档中有对应的功能描述。如果UI原型图中有需求未提及的元素或交互，**不得为其生成独立用例**
2. **测试点不越界**: 测试点的范围不能超出需求文档定义的功能边界。如果测试点描述了需求中没有的功能，以需求为准忽略超出的部分
3. **需求完整性校验**: 如果提供了需求文档，AI必须在输出前确认已覆盖需求的每一个主要功能点

### Requirement: 权重提示动态展示

系统 SHALL 在 prompt 中根据当前数据源组合显示：

* 当前可用的数据源及各自权重百分比

* 每个数据源的角色定位（核心依据/生成范围/验收标准）

* 缺失数据源的警告提示

## MODIFIED Requirements

### Requirement: generate\_test\_case\_enhanced() prompt

现有 prompt 的权重部分 SHALL 被替换为新的需求文档优先模型：

* 移除旧的 `source_count == 3 → 各1/3` 逻辑

* 替换为上述5种场景的权重分配

* 约束条款从8条扩展至10-12条（增加防偏离规则）
