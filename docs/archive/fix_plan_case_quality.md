## 修复原则

1. **最小侵入**: 优先修改 Prompt 和评分逻辑，不改变 Pipeline 架构
2. **向后兼容**: 修改不破坏旧版直接调用路径（TestCaseGenerationService）
3. **可度量**: 每项修复有明确的验证标准
4. **不推断**: 遇到不确定的点提问确认，不自行推断

## 逐项修复方案

### P0 + P1: 一个测试点生成多条用例 + 测试类型覆盖策略

**问题本质**: P0 和 P1 高度耦合，合并处理。

**当前状态**:
- Prompt 输出格式为单条用例 JSON 对象
- CaseGeneration 每个测试点调用一次 AI，期望返回 1 条用例
- `_parse_case_response` 已支持数组和单条 dict

**待确认点**:
- [ ] 每个测试点生成几条用例？建议 3-5 条
- [ ] 是否在 Prompt 中明确要求按测试类型分布生成？
- [ ] 生成多条时 max_tokens 是否需要上调？当前 3000

**初步方案**:
1. 修改 `ai_prompt_mixin.py` 的输出格式：单条对象 → 数组
2. 在 Prompt 中增加测试类型覆盖要求
3. 调整 `case_generation.py` 的 max_tokens
4. `_parse_case_response` 已兼容数组，无需修改

---

### P2: `_score_steps` 步骤质量评估

**当前状态**: 3步及以上 = 满分25，不区分步骤质量

**待确认点**:
- [ ] 步骤质量检查是否只看结构（每步是否有 action + expected_result），还是也要看语义？

**初步方案**:
- 增加结构完整性检查：每步是否同时包含 action 和 expected_result
- 评分规则：3步+每步完整=25, 3步+部分缺失=15, 2步+完整=20, 2步+缺失=10

---

### P3: `_score_expected_result` 评分细化

**当前状态**: 含模糊词→10分，不含→25分，两档过于粗糙

**待确认点**: 无

**方案**:
- 模糊词(5分): 仅含"正常"/"成功"等
- 部分具体(15分): 含具体交互描述但缺量化标准（如"跳转至报告页"）
- 可量化(25分): 含明确判定标准（如"弹窗文案为XXX"/"按钮置灰不可点击"）

判定规则：含模糊词→5; 不含模糊词但含交互动词(显示/跳转/弹出/置灰/隐藏)→15; 否则→25

---

### P4: 解析失败重试

**当前状态**: 解析失败直接标记 failed，不重试

**待确认点**:
- [ ] 重试次数？建议 1 次
- [ ] 重试时是否调整策略？建议简化 Prompt 去掉正反对比，降低 token 消耗

**初步方案**:
- 解析失败后重试 1 次，使用相同 Prompt
- 重试仍然失败则标记 failed

---

### P5: 用例去重

**待确认点**:
- [ ] 去重范围：同一测试点内？同一迭代内？同一项目内？
- [ ] 去重策略：标题相似度？步骤重叠度？还是两者结合？
- [ ] 去重时机：生成后立即去重，还是 Persist 前去重？

**初步方案**:
- 范围：同一测试点内去重（最常见场景）
- 策略：标题 Jaccard 相似度 > 0.6 视为重复，保留评分更高的
- 时机：CaseGeneration 生成后、QualityGate 评分前

---

### P6: `case_type` 硬编码

**当前状态**: `if not has_ui: case["case_type"] = "API"`

**待确认点**: 无

**方案**:
- 仅在 AI 未输出 case_type 时作为 fallback 默认值
- 不覆盖 AI 已输出的 case_type

---

### P7: 前置条件评分维度扩展

**当前状态**: 只检查 登录/网络/权限 三个关键词

**待确认点**:
- [ ] API 测试场景是否需要"登录"关键词？API 测试通常用 token 而非"登录"
- [ ] 是否增加"测试数据"维度？

**初步方案**:
- 增加 token/auth 关键词检测（覆盖 API 测试场景）
- 有内容但无任何关键词匹配时给 5 分（已修复）
- 不增加"测试数据"维度（按 Prompt 规则，测试数据应在步骤中创建而非前置条件中声明）

## 验证标准

| 问题 | 验证方式 |
|------|----------|
| P0+P1 | 同一测试点生成 ≥3 条不同类型用例 |
| P2 | 3步但缺 action/expected_result 的用例得分 < 25 |
| P3 | "提交成功并跳转至报告页" 得 15 分而非 10 分 |
| P4 | 解析失败后自动重试 1 次 |
| P5 | 同测试点内标题相似度 >0.6 的用例只保留 1 条 |
| P6 | AI 输出 case_type="manual" 时不被覆盖为 "API" |
| P7 | 前置条件含 "Bearer token" 时得分 > 0 |
