# 流程编排体验优化实施方案

## 1. 背景与目标

`AI生成用例` 页面中的流程编排区域当前更像一个完整画布编辑器：节点信息、按钮、连线、搜索、自动布局、路径播放等能力集中在同一个视图中。对新用户而言，页面流浏览、流程调整、节点详情查看混在一起，导致认知负担较高；当 UI 原型页面数量较多时，节点密集、文字拥挤、工具栏复杂，流程很难快速看懂。

本方案从用户体验和视觉设计角度重新规划流程编排区域，目标是把它从“复杂画布编辑器”优化为“可浏览、可理解、可调整的 UI 页面流工作台”。

### 1.1 体验目标

- 用户进入页面后先看懂整体 UI 页面流，而不是先面对复杂编辑工具。
- 用户能快速区分主干、分支、异常、旁路流程。
- 用户点击节点后能看到完整页面信息，而不是在小节点卡片中阅读大段文本。
- 用户调整主干顺序时使用更稳定的列表操作，而不是依赖画布拖拽。
- 用户需要编辑时再进入“调整”模式，减少默认视图的视觉噪音。

### 1.2 业务目标

- 提升 AI 生成测试用例前的 UI 流程整理效率。
- 降低流程编排的学习成本。
- 提高 `flow_sort_data` 中主干顺序、分支归属、异常路径的准确性。
- 保持现有生成主链路稳定，不引入后端接口变更。

## 2. 当前体验问题

### 2.1 信息层级混乱

当前节点卡片同时承载缩略图、流程类型、页面名称、摘要、元素统计、预览和编辑入口。节点数量变多后，用户很难判断当前应该看图、看名称还是看摘要。

### 2.2 工具栏负担过重

总览和调整操作混在一个工具栏中，搜索、自动布局、路径播放、Prompt 预览、完整度等功能同时出现。用户在“只是想看整体流程”时也会看到大量编辑按钮。

### 2.3 画布承担过多职责

画布既用于浏览结构，也用于调整顺序、选择节点、编辑类型、查看详情、连线和定位。所有操作都发生在节点和画布上，导致复杂度集中。

### 2.4 主干顺序不够直观

主干顺序通过节点位置和前移/后移按钮控制，不如列表拖拽直观。大量节点时，用户难以判断当前主干第几步、是否有缺失或重复。

### 2.5 复杂流程缺少理解辅助

当分支、异常、旁路较多时，用户缺少路径聚焦、泳道筛选、问题提示等辅助能力，无法快速理解某个节点从哪里来、到哪里去。

## 3. 目标交互模型

### 3.1 总览模式

总览模式用于浏览完整页面流。

- 默认进入总览模式。
- 只展示轻量节点、页面缩略图、页面名、类型色条和必要连线。
- 工具栏只保留模式切换和必要查看操作。
- 禁止直接编辑节点类型、连线和顺序。
- 点击节点时打开详情面板或预览，不在节点上堆叠操作。

### 3.2 调整模式

调整模式用于编辑流程结构。

- 显示自动布局、搜索、路径播放、完整度、智能识别等工具。
- 支持节点选择、类型切换、连线、删除、撤销。
- 支持主干步骤列表拖拽排序。
- 支持右侧详情面板编辑节点属性。

### 3.3 右侧详情面板

节点详情从节点卡片中迁移到右侧详情面板。

面板展示内容：

- 页面大图预览。
- 页面名称。
- 页面摘要。
- 元素统计。
- 当前流程类型。
- 上游页面。
- 下游页面。
- 预览截图。
- 设为主干、分支、异常、旁路。

### 3.4 主干步骤列表

主干顺序从画布拖拽为主，调整为列表操作为主。

- 展示所有主干节点。
- 支持上下拖拽排序。
- 点击步骤定位画布节点。
- 标记缺失顺序、重复顺序、孤立主干节点。
- 排序后同步更新 `flow_sort_data.nodes[].main_order`。

### 3.5 画布职责收敛

画布主要用于展示结构关系。

- 展示主干、分支、异常、旁路关系。
- 支持路径高亮和局部聚焦。
- 支持自动布局后的可视化检查。
- 不再承载全部详情和全部操作。

## 4. 视觉设计方案

### 4.1 整体布局

建议采用三段式工作台布局：

```text
顶部：流程概览信息 + 模式切换 + 当前状态
中间：主工作区
  左侧：主干步骤列表（调整模式显示）
  中间：页面流画布
  右侧：节点详情面板（选中节点后显示）
底部：流程问题提示或上下文质量提示
```

总览模式下隐藏左侧步骤列表和复杂工具，只保留画布与必要详情入口。

### 4.2 节点视觉

总览模式节点：

- 以截图为主体。
- 卡片高度降低。
- 只显示页面名、流程类型色条、主干序号。
- 不显示摘要、元素数量、悬浮操作按钮。
- 缩略图比例保持稳定，避免节点因文字长度抖动。

调整模式节点：

- 保留页面名、类型、截图。
- 摘要默认不显示在卡片内，移入右侧详情面板。
- 悬浮操作减少到必要动作，例如预览和快速改类型。
- 选中态、路径高亮态、搜索命中态要有清晰但克制的视觉差异。

### 4.3 工具栏视觉

总览模式工具栏：

- 模式切换。
- 适配全图。
- 可选：页面数量、主干数量、问题数量。

调整模式工具栏：

- 自动布局。
- 搜索页面。
- 撤销。
- 流程完整度。
- 智能识别跳转关系。
- 路径播放。
- 保存状态。

工具栏按钮使用图标为主，文字只用于模式切换和明确命令，避免长按钮挤压。

### 4.4 泳道布局

画布自动布局采用泳道思路：

- 主干流程横向排列，超过一定数量后自动换行。
- 分支流程挂在对应主干节点下方。
- 异常流程位于分支下方或独立异常泳道。
- 旁路流程位于主干下方的辅助区域。

视觉上通过轻量背景区分泳道，不使用大面积重色块。

### 4.5 路径聚焦

点击节点后：

- 当前节点高亮。
- 上游节点和连线高亮。
- 下游节点和连线高亮。
- 无关节点降低透明度。
- 右侧详情面板展示上下游页面列表。

## 5. 分阶段实施计划

## Phase 1：降低视觉噪音

### 目标

先解决“第一眼难看、难扫读、工具太多”的问题。

### 实施内容

- 总览模式只显示轻量节点。
- 总览模式隐藏编辑类按钮。
- 调整节点尺寸、间距、连线透明度。
- 优化 minimap 和画布空白区域。
- 保证一屏可见更多节点。

### 验收标准

- 默认进入总览模式。
- 总览模式不显示搜索框、路径播放、自动布局、Prompt、完整度等编辑工具。
- 节点文字不溢出。
- 页面数量较多时仍能快速看清主干走向。

## Phase 2：增加右侧详情面板

### 目标

把节点卡片中的详情信息迁移到独立面板，降低节点视觉负担。

### 实施内容

- 新增节点详情面板。
- 点击节点后打开或更新详情面板。
- 面板展示截图、名称、摘要、元素统计、上下游、流程类型。
- 面板提供预览和流程类型切换操作。
- 节点卡片内移除摘要和大部分操作按钮。

### 验收标准

- 点击节点后详情面板展示正确信息。
- 切换节点时面板内容同步更新。
- 关闭面板不影响画布选中和生成数据。
- 节点卡片明显更轻量。

## Phase 3：主干步骤列表

### 目标

让主干顺序调整从画布操作变成更稳定的列表操作。

### 实施内容

- 新增主干步骤列表。
- 列表展示主干节点序号、页面名称、状态。
- 支持拖拽排序。
- 支持点击步骤定位画布节点。
- 标记缺失顺序、重复顺序、孤立节点。
- 排序后同步更新 `main_order`。

### 验收标准

- 拖拽列表后主干顺序正确更新。
- 画布布局同步刷新。
- `getFlowSortSubmitData()` 输出的 `main_order` 正确。
- 列表操作不影响分支、异常、旁路节点数据。

## Phase 4：布局和路径理解增强

### 目标

提升复杂流程下的浏览和理解效率。

### 实施内容

- 自动布局改为“主干换行 + 分支挂载 + 异常下沉”。
- 点击节点后高亮上下游路径。
- 增加流程筛选：只看主干、显示分支、显示异常、显示全部。
- 增加流程问题提示：无入口、孤立节点、分支无归属、异常无回流。
- 支持按问题点击定位节点。

### 验收标准

- 大量节点下自动布局不横向无限拉长。
- 点击节点后能清楚看到上下游。
- 筛选状态不写入生成接口。
- 问题提示能定位到相关节点。

## 6. 数据与接口兼容性

### 6.1 不修改后端接口

P0/P1 阶段不修改后端接口，不新增必填字段，不改变现有 `flow_sort_data` 字段语义。

### 6.2 UI 状态不进入生成数据

以下状态仅作为前端 UI 状态：

- `displayMode`
- 搜索关键词
- 详情面板展开状态
- 路径高亮状态
- 流程筛选状态
- 折叠状态

这些状态不应进入 AI 生成接口。

### 6.3 主干列表只更新现有字段

主干步骤列表排序只更新：

```ts
nodes[].main_order
```

不新增生成接口字段。

### 6.4 布局保存策略

如果后续需要保存用户手动布局，建议独立设计布局字段或接口，例如：

```ts
view_meta?: {
  manual_position?: boolean
  layout_strategy?: string
}
```

该字段不应影响 AI 生成语义。

## 7. 测试方案

### 7.1 总览模式

- 默认进入总览模式。
- 只显示轻量节点和必要模式切换。
- 不显示编辑工具、搜索框、路径播放等复杂控件。
- 节点文字不溢出。
- 缩略图比例稳定。

### 7.2 调整模式

- 编辑工具正常出现。
- 节点可选中。
- 节点可切换流程类型。
- 节点可连线。
- 搜索、自动布局、撤销、完整度面板正常。

### 7.3 详情面板

- 点击节点后展示正确页面信息。
- 切换节点时内容同步。
- 关闭面板后画布状态不丢失。
- 类型切换后节点和面板同步更新。

### 7.4 主干步骤列表

- 拖拽排序后 `main_order` 正确。
- 画布节点顺序同步变化。
- 点击步骤可定位画布节点。
- 缺失顺序、重复顺序、孤立节点提示正确。

### 7.5 数据提交

- `flow_sort_data` 不包含 UI 临时状态。
- 主干排序后提交数据正确。
- 分支、异常、旁路数据不丢失。

### 7.6 视觉回归

需要覆盖以下视口：

- 1400x640
- 1605x800
- 768px 窄屏

检查点：

- 工具栏不换行混乱。
- 节点文字不遮挡截图。
- 右侧面板不遮挡画布核心内容。
- minimap 不覆盖重要节点。

## 8. 风险与约束

### 8.1 交互习惯变化

主干顺序从画布拖拽为主调整为列表排序为主，用户需要适应新的操作方式。建议保留原有前移、后移能力一段时间作为兼容。

### 8.2 画布状态复杂度增加

详情面板、路径高亮、筛选、步骤列表都会增加前端 UI 状态。需要明确这些状态不进入生成接口，避免污染数据。

### 8.3 自动布局影响已有手动布局

自动布局策略调整后，可能覆盖用户手动拖拽的位置。建议自动布局触发前给出明确按钮，不在普通切换模式时强制重排。

### 8.4 节点轻量化可能隐藏信息

摘要和元素统计移出节点后，用户需要通过详情面板查看。需要保证点击节点和详情展示足够明显。

## 9. 推荐优先级

### P0

- 总览模式视觉减负。
- 编辑工具只在调整模式显示。
- 节点卡片轻量化。
- 工具栏稳定布局。

### P1

- 右侧详情面板。
- 主干步骤列表。
- 点击节点定位详情。

### P2

- 泳道布局。
- 路径聚焦。
- 流程筛选。
- 问题提示定位。

## 10. 最终验收标准

- 用户默认看到的是清晰的页面流总览，而不是复杂编辑工具。
- 用户点击任意节点可以查看完整页面信息。
- 用户可以通过列表稳定调整主干顺序。
- 用户可以在调整模式完成类型切换、连线、搜索、自动布局。
- 生成接口数据结构保持兼容。
- 1400x640 视口下工具栏、节点、画布、详情面板均无明显遮挡或挤压。
