### B-06 `[分支]` CI 全量测试耗时压降（17:17 → 目标 <10 min）⏱ M ✅ 已结项（2026-11-12）

- **初测**：后端全量 `pytest tests/` 1037s（17:17），逼近 20 分钟红线；`ci.yml` 当时只跑 5 个子目录，全量未纳入必阻断。
- **判据**：全量纳入 CI 且测试步骤 wall time < 600s；`ci.yml` 增加全量 job（必阻断或独立提示类）。
- **结论：不能上 `pytest-xdist -n auto`（已实测，勿重复尝试）**。测试共享同一个 MySQL 库，跨进程并发互相制造行锁/死锁；MySQL 事务被回滚后销毁 SAVEPOINT，报错 `(1305) SAVEPOINT sa_savepoint_1 does not exist`。实测：
  | 配置 | 结果 | 耗时 |
  | --- | --- | --- |
  | 串行（基线） | 10232 passed / 0 failed | 18:12 |
  | `-n auto`（12 worker） | **11 failed / 106 errors** | 5:35 |
  | `-n auto --dist loadfile` | **6 failed / 78 errors** | 4:16 |
  | `-n 1`（单 worker） | 244 passed（与串行一致） | 0:30 |
  → 根因是**跨进程共享库**，非用例本身；彻底解法需 per-worker 独立库（CI 的 `test_user` 无 `CREATE DATABASE` 权限）或把异步用例全部并入同一事务 fixture（测试基建大改），不在本波范围。
- **采用方案：同库 + 分片串行**。`pytest-split` 按 `.test_durations`（本地串行实测时长，已入库）把全量切成 4 片，CI 用 matrix 4 个 job 并行跑，单片只做串行执行，从根本上避免同库并发。

- **配套改动**：
  1. `ci.yml` 新增 `backend-full`（matrix 4 分片，**必阻断**，`fail-fast: false`），完整跑 `pytest tests -q --splits 4 --group N`；
