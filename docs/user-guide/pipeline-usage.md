# Pipeline 迭代操作手册

本手册面向 QA 团队，介绍如何创建迭代、触发 Pipeline、查看进度及理解各场景差异。

---

## 一、核心概念

### 1.1 迭代（Iteration）

迭代是 Pipeline 运行的基本单元，代表一次完整的用例生成/回归周期。

**生命周期**：

```
draft → in_pipeline → in_review → finalized → archived
```

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| `draft` | 草稿，已创建但未启动 | 添加输入、编辑信息、删除 |
| `in_pipeline` | Pipeline 运行中 | 查看进度 |
| `in_review` | 评审中，等待人工确认 | 评审决策、定稿 |
| `finalized` | 已定稿 | 归档 |
| `archived` | 已归档（终态） | — |

> **注意**：迭代状态由系统自动驱动，用户不可手动修改。

### 1.2 Pipeline 场景

系统根据输入完整度和项目类型自动选择场景：

| 场景 | 适用条件 | 核心步骤 |
|------|---------|---------|
| 场景 1：全输入新项目 | PRD + 测试点 + UI 原型齐全 | 信号采集 → 测试点对齐 → 用例生成 → 质量门禁 → 持久化 |
| 场景 2：无 UI 新项目 | PRD + 测试点，无 UI 原型 | 信号采集 → 用例生成 → 质量门禁 → 持久化 |
| 场景 3：仅 UI 新项目 | 只有 UI 原型，无 PRD/测试点 | 信号采集 → 反推业务能力 → 候选提取 → 对齐 → 生成 → 质量门禁 → 持久化 |
| 场景 4：旧项目回归 | 有新 PRD，历史用例需回归 | 信号采集 → 历史指纹 → 对齐 → 双向扫描 → 协调 → 生成 → 质量门禁 → 持久化 |
| 场景 5：旧项目无新 PRD | 无新 PRD，纯历史回归 | 信号采集 → 历史指纹 → 反推 → 对齐 → 双向扫描 → 协调 → 生成 → 质量门禁 → 持久化 |

## 二、创建迭代

### 2.1 操作步骤

**入口**：迭代管理 → 新建迭代

1. 点击「新建迭代」按钮
2. 填写基本信息：

| 字段 | 必填 | 说明 |
|------|------|------|
| 项目 | 是 | 选择关联项目 |
| 迭代名称 | 是 | 如"V2.1 回归测试" |
| 版本号 | 否 | 如"2.1.0" |
| 描述 | 否 | 迭代目标说明 |
| 起止日期 | 否 | 计划周期 |

3. （可选）选择「基于历史迭代创建」，指定 `base_iteration_id`
4. 点击「创建」

### 2.2 基于历史迭代创建

适用场景：回归测试时，基于上一轮迭代的用例进行增量更新。

操作：在创建对话框中勾选「基于历史迭代」，选择目标迭代。系统将自动继承历史迭代的输入和用例作为基线。

---

## 三、添加迭代输入

迭代输入是 Pipeline 生成用例的原料，支持 5 种类型：

| 输入类型 | 说明 | 格式要求 |
|---------|------|---------|
| `prd` | 产品需求文档 | 文本/PDF/Word |
| `prototype` | UI 设计原型 | 图片（PNG/JPG） |
| `xmind` | XMind 思维导图 | .xmind 文件 |
| `testpoint` | 测试点清单 | 系统内测试点 |
| `supplement_form` | 补充表单 | 结构化数据 |

### 3.1 操作步骤

1. 进入迭代详情页
2. 在「输入」区域点击「添加输入」
3. 选择输入类型
4. 上传文件或选择已有资源
5. 系统自动计算 `content_hash` 去重，重复输入会被忽略
6. 确认添加

### 3.2 输入与场景的关系

| 输入组合 | 自动选择场景 |
|---------|------------|
| PRD + 测试点 + UI 原型 | 场景 1 |
| PRD + 测试点（无 UI） | 场景 2 |
| 仅 UI 原型 | 场景 3 |
| 新 PRD + 历史用例 | 场景 4 |
| 无新 PRD + 历史用例 | 场景 5 |

---

## 四、触发 Pipeline

### 4.1 操作步骤

1. 确认迭代输入已添加完整
2. 在迭代详情页点击「启动 Pipeline」
3. 系统自动选择场景并开始运行
4. 迭代状态从 `draft` 变为 `in_pipeline`

### 4.2 注意事项

- Pipeline 启动后不可暂停，只能等待完成或取消
- 运行期间不可修改迭代输入
- 运行期间不可删除迭代

---

## 五、查看 Pipeline 进度

### 5.1 进度页面

**入口**：迭代详情 → 查看进度

进度页面展示以下信息：

| 区域 | 内容 |
|------|------|
| 运行概览 | 运行 ID、迭代 ID、Pipeline 版本、起止时间、总耗时 |
| 步骤列表 | 每个步骤的名称、状态、起止时间、耗时、错误信息、降级标记、重试次数 |
| 产物列表 | 产物类型、置信度、Schema 版本、创建时间 |

### 5.2 步骤状态说明

| 状态 | 说明 |
|------|------|
| `pending` | 等待执行 |
| `running` | 执行中 |
| `done` | 执行完成 |
| `failed` | 执行失败 |
| `skipped` | 被跳过 |
| `degraded` | 降级执行（如 CTE 不可用降级为 BFS） |

### 5.3 自动轮询

页面每 5 秒自动刷新运行中 Pipeline 的状态，无需手动刷新。

### 5.4 等待用户确认

当 Pipeline 状态为 `waiting_for_user` 时，页面自动弹出确认对话框。用户确认后 Pipeline 继续运行。

---

## 六、Pipeline 完成后

Pipeline 运行完成后，迭代自动进入 `in_review` 状态，进入评审阶段。详见 [评审工作流操作手册](./review-workflow.md)。

## 七、常见问题

### Q1: Pipeline 运行失败怎么办？

1. 查看步骤列表中 `failed` 状态的步骤
2. 点击步骤查看错误信息
3. 常见原因：
   - AI 服务不可用（检查 DeepSeek API 配置）
   - 输入数据格式错误（检查 PRD/原型是否有效）
   - 数据库连接超时（检查 MySQL 状态）
4. 修复问题后，创建新迭代重新运行

### Q2: 场景选择不正确？

场景由系统根据输入类型自动选择。如果结果不符预期：
- 检查是否遗漏了某种输入类型
- 确认 UI 原型是否成功上传
- 确认项目是否有历史用例（影响场景 4/5 判定）

### Q3: Pipeline 运行时间过长？

正常耗时参考：
- 场景 1/2：5-15 分钟（取决于 PRD 长度和测试点数量）
- 场景 3：10-20 分钟（需要反推业务能力）
- 场景 4/5：15-30 分钟（双向扫描 + 协调）

如超过上述时间，检查：
- AI 服务响应是否正常
- 是否有步骤反复重试
- 数据量是否异常大

### Q4: 如何取消正在运行的 Pipeline？

目前 Pipeline 不支持暂停。如需中止，请联系管理员手动处理。
