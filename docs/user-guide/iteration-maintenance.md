# 跨迭代用例维护操作指南

本手册介绍迭代定稿后的用例维护操作，包括生命周期管理、血缘关系追踪、后验质量分解读和跨迭代回归策略。

---

## 一、用例生命周期管理

### 1.1 生命周期状态流转

```
draft → active → pending_review → needs_modify → active（修改后）
                 ↘ locator_broken → active（修复后）
                                   ↘ deprecated → archived
```

| 状态 | 说明 | 触发条件 |
|------|------|---------|
| `draft` | 草稿 | AI 生成后的初始状态 |
| `active` | 活跃 | 评审采纳后自动激活 |
| `pending_review` | 待审核 | 提交审核时 |
| `needs_modify` | 需修改 | 评审判定为 modify |
| `locator_broken` | 定位失效 | 执行时元素定位失败 |
| `deprecated` | 已废弃 | 评审判定为 deprecate |
| `archived` | 已归档 | 手动归档或系统自动归档 |

### 1.2 状态变更操作

| 操作 | 入口 | 说明 |
|------|------|------|
| 激活用例 | 用例详情 → 编辑 | 修改后保存自动激活 |
| 废弃用例 | 用例列表 → 废弃 | 标记为不再使用 |
| 归档用例 | 用例列表 → 归档 | 终态，不可恢复 |
| 修复定位 | 用例详情 → 编辑定位器 | 修复后状态从 locator_broken 恢复 |

## 二、血缘关系追踪

### 2.1 什么是血缘关系

用例血缘关系记录了用例之间的父子衍生关系。当一个用例从另一个用例派生（如拆分、变体）时，系统自动建立 `parent_case_id` 关联，形成血缘树。

### 2.2 查看血缘树

**入口**：用例详情 → 血缘关系

血缘关系区域展示：

| 区域 | 说明 |
|------|------|
| 摘要信息 | 根节点编号、链长度、警告阈值 |
| 祖先链 | 从根节点到当前用例的祖先路径（横向箭头展示） |
| 后代树 | 从根节点出发的完整子树（树形展开） |
| 警告提示 | 链长度 ≥ 阈值时显示红色警告 |

### 2.3 状态徽标

每个血缘节点显示生命周期状态徽标：

| 状态 | 徽标颜色 | 含义 |
|------|---------|------|
| 草稿 | 灰色 | AI 生成待确认 |
| 活跃 | 绿色 | 已确认可用 |
| 待评审 | 橙色 | 等待审核 |
| 需修改 | 红色 | 审核未通过 |
| 定位失效 | 红色 | UI 变更导致定位失败 |
| 已废弃 | 灰色 | 不再使用 |
| 已归档 | 灰色 | 终态 |

### 2.4 链长度警告

当血缘链长度 ≥ 警告阈值（默认 3）时，系统显示警告提示：

> ⚠️ 血缘链长度 N 已达到警告阈值 M，建议拆分用例

**建议**：链过长意味着用例继承层次过深，维护成本高。考虑将深层用例拆分为独立用例。

### 2.5 节点跳转

点击血缘树中的任意节点，可跳转到该用例的详情页。当前用例会标记「当前」标签。

## 三、后验质量分

### 3.1 什么是后验质量分

后验质量分是基于用例实际运行数据（评审结果 + 执行结果）计算的质量评分，范围 0-100 分。

### 3.2 计算公式

```
后验质量分 = (评审通过率 × 0.5 + 执行通过率 × 0.3 + (1 - 修改率) × 0.2) × 100
```

| 维度 | 权重 | 数据来源 |
|------|------|---------|
| 评审通过率 | 50% | 评审中 `keep` 判定的比例 |
| 执行通过率 | 30% | 执行状态为 `passed` 的比例 |
| 修改率 | 20% | 评审中需修改/定位失效判定的比例 |

### 3.3 分数解读

| 分数范围 | 等级 | 建议 |
|---------|------|------|
| 80-100 | 优秀 | 用例质量高，可放心使用 |
| 60-79 | 良好 | 整体可用，局部可优化 |
| 40-59 | 一般 | 需要关注，建议审查修改 |
| 0-39 | 较差 | 建议重写或废弃 |

### 3.4 特殊情况

| 情况 | 显示 | 原因 |
|------|------|------|
| 无执行记录 | `—` | 执行次数不足最低样本要求 |
| 无评审数据 | 基于默认值计算 | 评审通过率默认取 0.5 |

### 3.5 批量回填

历史用例可能缺少后验质量分。管理员可通过脚本批量计算并回填：

```bash
# 预览模式（不写入数据库）
python scripts/compute_posterior_score.py --project-id 1 --dry-run

# 正式执行
python scripts/compute_posterior_score.py --project-id 1

# 限制处理数量
python scripts/compute_posterior_score.py --project-id 1 --limit 100
```

## 四、跨迭代回归策略

### 4.1 基于历史迭代创建回归

**操作步骤**：

1. 创建新迭代时，选择「基于历史迭代创建」
2. 指定上一轮迭代作为基线
3. 添加新的 PRD 或需求变更作为输入
4. 启动 Pipeline，系统自动选择场景 4（有新 PRD）或场景 5（无新 PRD）

### 4.2 双向扫描机制

回归场景下，Pipeline 执行双向扫描：

| 扫描方向 | 目的 | 产物 |
|---------|------|------|
| 后向扫描（Backward Scan） | 检查现有用例是否仍有效 | 废弃/修改建议 |
| 前向扫描（Forward Scan） | 发现新的测试需求 | 新用例建议 |

### 4.3 协调（Reconciliation）

当双向扫描结果冲突时（如后向建议废弃、前向建议新增同类用例），系统自动协调，避免冗余。

## 五、用例维护日常操作

### 5.1 定位失效修复

**触发条件**：执行时元素定位失败，用例状态变为 `locator_broken`

**修复步骤**：

1. 进入用例详情页
2. 切换到技术视图
3. 找到定位失效的步骤（标红显示）
4. 点击「编辑定位器」
5. 更新定位表达式（CSS/XPath/ARIA）
6. 点击「测试」验证
7. 保存后状态自动恢复为 `active`

### 5.2 批量定位补充

**入口**：用例详情 → 批量定位

适用于多个步骤同时缺少定位器的情况。详见 [操作手册 §4.2](../操作手册.md)。

### 5.3 用例纠正

**入口**：执行记录 → 失败步骤 → 纠正

**步骤**：

1. 从执行失败记录进入纠正模式
2. 标记失败步骤
3. 查看 AI 智能建议
4. 修改步骤或定位器
5. 快速验证修复效果
6. 提交验证

## 六、质量分析

### 6.1 用例质量分析页

**入口**：用例列表 → 质量分析

展示项目级用例质量概览：

- 先验质量分分布（AI 生成时评估）
- 后验质量分分布（实际运行后评估）
- 生命周期状态分布
- 定位覆盖率

### 6.2 质量对比

| 指标 | 先验分 | 后验分 |
|------|--------|--------|
| 数据来源 | 用例结构特征 | 评审 + 执行结果 |
| 计算时机 | AI 生成时 | 有运行数据后 |
| 可靠性 | 中等（预测性） | 高（实证性） |

建议：先验分用于快速筛选，后验分用于长期维护决策。

## 七、常见问题

### Q1: 血缘链过长怎么处理？

1. 查看血缘树，找到链中可拆分的节点
2. 将深层用例的 `parent_case_id` 解除关联
3. 或将深层用例重构为独立用例

### Q2: 后验质量分为空？

可能原因：
- 用例从未执行过（执行次数不足最低样本要求）
- 用例从未参与评审
- 历史用例未回填后验分

解决：运行批量回填脚本 `compute_posterior_score.py`

### Q3: 跨迭代用例如何保持同步？

1. 基于历史迭代创建新迭代时，系统自动继承基线用例
2. Pipeline 双向扫描会检测变更
3. 评审阶段确认保留/修改/废弃
4. 最终化后变更生效

### Q4: 废弃用例的子用例怎么处理？

废弃用例时，系统级联废弃其所有子用例。如需保留子用例，需先解除父子关系（修改 `parent_case_id`），再废弃父用例。

### Q5: 如何查看用例的修改历史？

进入用例详情页 → 版本历史，可查看所有修改记录并支持版本回滚。
