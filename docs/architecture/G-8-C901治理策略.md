## 2. 判定口径

- 阈值：`[lint.mccabe] max-complexity = 10`（宏口径），**不上调**。上调阈值等于把 150 处藏起来，与 B-05「门禁失信」同类。
- 复杂度测的是**分支路径数**。拆分的目标是「一个函数只讲一件事」，不是把 `if` 搬进 helper 换个地方堆。
- **反例**：状态机 / 回退扫描类函数，分支数量由外部输入形态决定，拆开需跨函数传 5–8 个状态参数，可读性反而下降 → 允许豁免（见 §4）。

## 4. 豁免标准（三条**全部**满足才可豁免）

1. 函数是**显式状态机 / 解析回退扫描**：分支对应外部输入形态（JSON 截断、流式事件、OCR 噪声），不是业务规则；
2. 拆分需新增 ≥3 个参数，或需跨函数共享可变状态（`self.xxx` 之外的局部状态）；
3. 已有测试锁定行为，且**行内 `# noqa: C901` 注明理由** + 本文件 §7 登记表追加一行。

## 6. 每批护栏（缺一不可）

```powershell

python -c "import app.main; print('ok')"              # 防 re-export 断裂
python -m pytest <本批相关目录> -q                     # 定向回归
```

批次**合入前**跑全量：`python -m pytest tests -q`（基线 **10435 passed / 53 skipped / 0 failed**，21m46s；10419 → 10435 为 B1 新增 16 例直测）。

## 7. 红线

- **禁全仓 `ruff check app --fix`**：`ruff.toml` 已记录实测后果——会删 re-export 转发符号（`_normalize_iteration_name` 等），导致 `import app.main` 失败。逐文件 + 逐规则推进。
- **端点保持 `async def` + `Depends(get_db)`**；禁止新增 `async_get_db`（收敛门禁锁定 9 处 / 2 文件，超预算即 CI 红）。
- **不改事务边界 / 异常映射 / 审计埋点顺序**；DB 调用一律经 `db_async_compat`（唯一入口约定，见交接 D-6）。
- **服务层单文件 ≤400 行**（`tests/services/test_service_refactor.py` 硬断言）——拆函数会引入新文件与 import，需同步控制行数；`runtime.py` 已因 format 折行触发过该护栏。
- **覆盖率 ≥80%**（CI `--cov-fail-under=80`）不得下降；纯搬迁优先，必要的新增测试随批提交。
- **每批必须可单独 revert**：不跨批改同一文件，不在一批里混入无关清理。

4. 每批 commit 满足 §5 边界，且能从历史中单独 revert 而不破坏其它批。

## 10. 排期与风险

- **估工**：150 处 × 0.5–1h ≈ **20–30 人日**，按 §5 六批推进，每批 1–2 天（B4 单独加倍）。
- **最大风险**：`test_execution_engine` 的 mixin 拆分——同域 22 处且被执行链路深度复用，行为漂移极难定位。缓解：**先补测试再拆**，单批单文件，拆完立刻跑该域全量。
- **次大风险**：端点拆分时顺手动权限/事务顺序 → 只允许「提取」，不允许「重排」。
- **回滚成本**：每批独立 commit + 不改同一文件跨批 → revert 单批即可，最坏退回计数门禁预算值。
