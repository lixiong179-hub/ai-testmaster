# AI-TestMaster 项目操作手册

## 一、项目概述

AI-TestMaster 是一个 AI 驱动的 UI 自动化测试平台，支持 Web 和移动端应用的自动化测试。

### 核心能力

- **AI 录制** — 自然语言描述测试步骤，AI 自动识别页面元素
- **MCP 智能定位** — 基于 Playwright MCP 的 Accessibility Tree 定位，零 VLM 成本
- **盘点项目的使用流程吧，输出项目操作手册** — 一次性为整个用例补充所有元素的定位器
- **AI 自愈执行** — 执行失败时自动尝试修复，元素变化也能继续执行
- **多端支持** — Web（Chrome/Firefox/WebKit）、Android App、iOS App

## 二、项目管理

### 2.1 创建项目

**入口**: 项目列表 → 新建项目

**步骤**:

1. 点击「新建项目」按钮
2. 填写项目名称和描述
3. 选择项目类型：
   - `Web` — 浏览器自动化测试
   - `APP` — 移动端 App 测试
   - `All` — 同时支持 Web 和 APP
4. 配置 Web 环境（URL 地址）
5. 配置移动端设备（Android/iOS）
6. 点击「创建」

**配置项说明**:

| 配置项    | 说明           | 示例                      |
| ------ | ------------ | ----------------------- |
| 项目名称   | 项目标识         | 电商后台管理系统                |
| 项目类型   | Web/APP/All  | Web                     |
| Web 环境 | 被测系统 URL     | <http://localhost:8080> |
| 设备平台   | Android/iOS  | Android                 |
| 设备 ID  | 连接的真机或模拟器 ID | 127.0.0.1:5555          |

### 2.2 项目配置

**入口**: 项目详情 → 配置

**可配置项**:

- 环境变量配置
- 设备配置
- 执行超时时间
- 重试次数

## 三、测试用例管理

### 3.1 创建用例

**入口**: 项目详情 → 用例管理 → 新建用例

**步骤**:

1. 点击「新建用例」按钮
2. 填写用例名称
3. 选择用例类型：
   - `UI自动化` — Web/App 界面测试
   - `接口测试` — API 测试（开发中）
4. 填写用例描述
5. 点击「创建」

### 3.2 编写测试步骤

**入口**: 用例详情 → 步骤列表

**步骤格式**:

```
操作 | 操作描述 | 测试数据 | 预期结果
```

**示例**:

| 操作类型     | 操作描述     | 测试数据                       | 预期结果           |
| -------- | -------- | -------------------------- | -------------- |
| navigate | 打开登录页面   | <http://example.com/login> | 页面加载成功         |
| click    | 点击用户名输入框 | <br />                     | 输入框获得焦点        |
| input    | 输入用户名    | testuser                   | 显示输入内容         |
| input    | 输入密码     | 123456                     | 显示\*\*\*（密码加密） |
| click    | 点击登录按钮   | <br />                     | 跳转到首页          |
| verify   | 验证用户名显示  | testuser                   | 显示正确           |

**操作类型说明**:

| 操作类型        | 说明    | 必需参数       |
| ----------- | ----- | ---------- |
| navigate    | 打开页面  | url        |
| click       | 点击元素  | 元素描述       |
| input       | 输入文本  | 元素描述 + 文本  |
| verify      | 验证内容  | 验证表达式      |
| hover       | 悬停    | 元素描述       |
| select      | 选择下拉项 | 元素描述 + 选项值 |
| switch      | 切换框架  | 框架ID或名称    |
| execute\_js | 执行JS  | JS代码       |

### 3.3 录制模式

**入口**: 用例详情 → 开始录制

**步骤**:

1. 点击「开始录制」按钮
2. 系统打开浏览器（Chrome）
3. 在浏览器中进行操作，AI 自动识别并生成步骤
4. 完成后点击「停止录制」

**录制配置**:

- 跳过已录制步骤 — 避免重复
- 启用前置条件 — 自动执行登录等前置操作
- 截图模式 — 每次操作后截图

## 四、元素定位系统

### 4.1 定位方式

系统支持 **6 种定位方式**，优先级从高到低：

| 定位类型     | 说明                 | 示例                                  |
| -------- | ------------------ | ----------------------------------- |
| `CSS选择器` | CSS Selector       | `#submit-btn`                       |
| `ARIA角色` | Accessibility Role | `getByRole('button', {name: '登录'})` |
| `文本定位`   | 可见文本匹配             | `getByText('提交')`                   |
| `引用定位`   | MCP 引用 ID          | `ref:abc123`                        |
| `XPath`  | XML 路径             | `//button[@id='submit']`            |
| `视觉坐标`   | 截图+AI识别            | `{x: 100, y: 200}`                  |

### 4.2 批量元素定位

**入口**: 用例详情 → 批量定位

**触发条件**: 用例中的元素缺少定位器时

**步骤**:

1. 点击「批量定位」按钮
2. 打开批量定位对话框
3. 配置选项：
   - `MCP定位引擎` — 开启使用 Playwright MCP（推荐）
   - `跳过已有` — 跳过已有定位器的元素
   - `执行前置操作` — 先执行登录等前置步骤
4. 点击「开始定位」
5. 等待 AI 识别完成
6. 查看结果：成功/失败/置信度

**MCP vs VLM 对比**:

| 维度   | MCP 模式     | VLM 模式    |
| ---- | ---------- | --------- |
| 定位速度 | <300ms/元素  | 3-5秒/元素   |
| 成本   | ≈0（普通 LLM） | ¥0.002/元素 |
| 准确性  | 确定性 DOM 操作 | 依赖截图质量    |
| 适用场景 | 有规律的管理系统   | 复杂的定制化界面  |

### 4.3 单元素定位

**入口**: 步骤详情 → 编辑定位器

**步骤**:

1. 点击步骤行的「编辑」按钮
2. 在定位器输入框中填写定位表达式
3. 点击「测试」验证定位是否正确
4. 点击「保存」

**定位表达式语法**:

```
# CSS 选择器
css:#username

# ARIA 角色（推荐）
role:button[登录]

# 文本定位
text:提交

# XPath
xpath://button[@id='submit']

# 引用（仅 MCP 模式）
ref:abc123
```

## 五、测试执行

### 5.1 执行配置

**入口**: 执行页面 → 执行配置

**配置项**:

| 配置项     | 说明             | 默认值            |
| ------- | -------------- | -------------- |
| 执行环境    | Web URL 或设备 ID | 项目配置           |
| 可见模式    | 执行时是否显示浏览器     | headless=false |
| MCP定位引擎 | 是否启用 MCP 定位    | true（推荐）       |
| AI自愈    | 失败时自动尝试修复      | false          |
| 视频录制    | 执行过程全程录制       | false          |
| 截图策略    | 失败时/每步/从不      | 失败时            |

### 5.2 执行模式

| 模式      | 说明               | 推荐场景    |
| ------- | ---------------- | ------- |
| `智能模式`  | 优先使用缓存，失败后 AI 识别 | 回归测试    |
| `实时识别`  | 每次都重新识别元素        | 新录制用例调试 |
| `预处理模式` | 执行前批量补充定位        | 大批量用例预热 |

### 5.3 执行流程

```
┌─────────────────────────────────────────────────────────────┐
│                     测试执行流程                               │
│                                                              │
│  1. 初始化浏览器 ──→ 2. 执行前置条件（登录等）               │
│                              │                               │
│                              ▼                               │
│                   3. 逐条执行测试步骤                         │
│                              │                               │
│            ┌─────────────────┼─────────────────┐             │
│            ▼                 ▼                 ▼             │
│     定位成功 ✓           定位失败            断言失败        │
│            │                 │                 │             │
│            ▼                 ▼                 ▼             │
│     执行操作            AI自愈尝试         截图记录         │
│            │                 │                 │             │
│            ▼                 ▼                 ▼             │
│     验证预期结果      自愈成功→继续      标记失败→停止     │
│            │                 │                               │
│            └─────────────────┘                               │
│                              │                               │
│                              ▼                               │
│                   4. 生成执行报告                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.4 查看执行结果

**入口**: 执行记录 → 详情

**报告内容**:

- 执行概览：成功率、通过率、总时长
- 步骤详情：每步的状态、耗时、截图
- 失败原因：定位失败、断言失败、异常
- 自愈记录：哪些步骤触发了自愈

## 六、AI 自愈机制

### 6.1 触发条件

当执行过程中元素定位失败时，系统会尝试 AI 自愈：

```
定位器无效
     │
     ▼
检查 AI_SELF_HEALING_ENABLED
     │
     ├─── true ──→ MCP 重新定位
     │                    │
     │           ┌────────┴────────┐
     │           ▼                 ▼
     │      自愈成功            自愈失败
     │           │                 │
     │           ▼                 ▼
     │      使用新定位器      标记失败
     │           │                 │
     └─── false ──→ 标记失败 ←────┘
```

### 6.2 自愈策略

| 优先级 | 策略                     | 说明            |
| --- | ---------------------- | ------------- |
| 1   | MCP Accessibility Tree | 利用 DOM 结构重新定位 |
| 2   | 视觉模型兜底                 | VLM 截图识别（成本高） |

### 6.3 配置自愈

**配置位置**: 执行配置 → AI自愈开关

**建议**:

- 回归测试：关闭（使用已有定位器，速度快）
- 新用例调试：开启（自动修复定位问题）

## 七、UI 原型解析

### 7.1 功能说明

将 UI 设计原型图（摹客等工具导出）解析为结构化页面信息，自动识别：

- 页面名称和目的
- 页面元素（按钮、输入框、文本等）
- 元素布局和结构
- 页面流转关系

### 7.2 解析模式

| 模式         | 说明           | 成本       | 适用场景    |
| ---------- | ------------ | -------- | ------- |
| `文本模式`（推荐） | OCR + 普通 LLM | ≈0       | 文字密集型页面 |
| `视觉模式`     | 视觉模型直接解析     | ¥0.002/图 | 需要布局信息  |

### 7.3 使用流程

**入口**: 需求管理 → UI原型 → 上传原型

**步骤**:

1. 上传 UI 原型图片（支持 PNG/JPG）
2. 选择解析模式（默认文本模式）
3. 点击「解析」
4. 查看解析结果：
   - 识别的页面元素列表
   - 元素类型和描述
   - 预估的流转关系
5. 可对识别结果进行编辑和确认
6. 一键生成测试用例初稿

## 八、用例质量管理

### 8.1 质量评分

系统自动评估用例质量，从 4 个维度打分：

| 维度  | 权重  | 评分项                 |
| --- | --- | ------------------- |
| 复杂度 | 30% | 步骤数量、操作多样性、数据依赖     |
| 冗余度 | 30% | 重复步骤、相似用例、不必要步骤     |
| 覆盖率 | 40% | 元素覆盖率、执行历史覆盖率、断言覆盖率 |

### 8.2 优化建议

系统根据质量分析给出优化建议：

- 合并重复步骤
- 增加必要的断言
- 简化复杂的步骤序列
- 补充缺失的定位器

## 十、常见问题

### Q1: 批量定位失败怎么办？

**排查步骤**:

1. 检查浏览器是否正常打开
2. 检查页面是否完全加载
3. 检查元素是否在可视区域内
4. 尝试切换 MCP/VLM 模式
5. 手动录制定位器

### Q2: AI 自愈不生效？

**排查步骤**:

1. 确认 `AI_SELF_HEALING_ENABLED=true`
2. 确认执行的是 Web 端用例（非移动端）
3. 检查 MCP Server 是否正常运行
4. 查看执行日志中的自愈尝试记录

### Q3: 如何选择 MCP 还是 VLM 模式？

**选择建议**:

- 管理后台、表格页面、表单页面 → **MCP**（快速、稳定、低成本）
- 复杂动画、自定义控件、Canvas → **VLM**（需要视觉理解）

### Q4: 执行速度太慢？

**优化建议**:

1. 使用 MCP 模式替代 VLM
2. 关闭不必要的截图
3. 使用智能模式替代实时识别
4. 批量执行代替单条执行
