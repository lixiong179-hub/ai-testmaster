## 3. 关键决策（新窗口必须知道，避免走回头路）

| # | 决策 | 理由 | 影响 |
| --- | --- | --- | --- |
| D-1 | **不删除异步引擎 / `AsyncPrimarySessionLocal` / `async_*` 入口** | `AsyncPrimarySessionLocal` 51 处、`run_async_coro_in_thread` 46 处被后台任务、SSE 流、self-test 依赖；删即全站崩 | 原「`sessionmaker` 4→2 / `_db` 8→4」判据**作废**，勿再按旧判据验收 |
| D-2 | **`storage/*` 的 async 方法不改造** | 端点本身 `async def`，可直接 `await` 存储；异步的是 IO 而非 DB | B-14 原「前置改造」前提不成立，直接迁移端点即可 |
| D-3 | **测试壳 `_SyncBackedAsyncSession` 保留** | 反向删除会让 async fixture 失去与同步端点的事务可见性 | 阶段四原「移除测试壳」计划已修订 |
| D-4 | **SSO 不设永久例外** | `oidc`/`saml` 的异步部分只有 httpx，DB 可行兼容层 | 门禁白名单无豁免项，仅剩定义处 |
| D-5 | **`User` 的 SSO 列以迁移为准补齐 ORM** | 迁移 `20260730_add_oidc_fields` / `add_saml_fields` 已建列，模型漏字段 | 不改库结构，仅补 ORM 声明；`nullable + index` |
| D-6 | **`get_async` 必须经兼容层，不用 `asyncio.to_thread(db.get, ...)`** | AsyncSession 下 `to_thread` 会返回未 await 的协程 | 兼容层是唯一 DB 调用入口约定 |
| D-7 | **禁止新增 `async_get_db` 使用** | 门禁即为约束载体 | 任何端点/服务新增 → CI 失败，属预期行为 |
