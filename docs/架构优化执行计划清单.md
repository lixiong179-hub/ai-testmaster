## 14. 执行顺序与依赖

```
M0 ✅  A-1 ─┬─ A-2 ─ A-3 ─┬─ A-4 ─── A-5（本清单）
            └─────────────┘
M1 ✅  R0-1 ─ R0-2 ─ R0-3 ─ R0-4       （互不依赖，风险由低到高）
D  ✅  D-1 / D-2 / D-4 已完成；D-3 废弃

M2 ⬜  R1-1 ─ R1-2 ─ R1-3                      第 1 波（低风险、见效快）
       R4-4 ────────────────────────────────┘
M3 ⬜  R2-1 ─ R2-2 ─ R2-3                      第 2 波（工程量大但机械）
       R4-1 ─ R4-2 ─ R4-3 ───────────────────┘   ← 依赖 R2-1（范式定了再分包）
M4 ⬜  R3-1 ─ R3-2 ─ R3-3                      第 3 波（能力建设）
M5 ⬜  R5-1 ─┬─ R5-2                            第 4 波（架构演进，需独立立项）
             └─ R5-3 ────────────────────────────（可提前并行）
```

**顺序理由**：
1. **先 R1 后 R2**——R1 让已有投入变现，是「最短路径见收益」；R2 是欠账清偿，可稍后。
2. **R4-1（领域分包）必须在 R2-1（范式归一）之后**——否则分包要跟着范式再改一次。
3. **R3 在 R2 之后**——智能能力依赖干净的执行与数据层。
4. **R5 最后且独立立项**——唯一架构级改动，风险与工作量均为最高。
5. **R5-3（PR CI）可随时启动**——不依赖其他任务，且能提升后续所有改动安全性。

**通用纪律（每项任务执行时遵守）**：
- 产出物**先 `git add` 再继续**（未跟踪文件零保护）
- 改一处跑一次相关测试
- 判断以**磁盘实况**为准，不依赖记忆
- 计数类核验必须避开 §15 的命令陷阱

## 15. 命令陷阱速查（避免误判）

1. `ls -1 _*.log _*.txt _* | wc -l` → **重复计数**；应用 `ls -1 _* | wc -l`。
2. `ls -1 app/api/v1/endpoints/_*.py` → **会匹配 `__init__.py`**；须加 `grep -v __init__`。
3. `grep -c "include_router"` → 含文件头注释；应用 `grep -c "app.include_router("`。
4. `grep -rn "\.delay(\|apply_async("` → 命中 docstring；须排除注释行。
5. 本机 bash 需前缀 `export PATH="/usr/bin:/bin:/usr/local/bin:$PATH"`，否则 `ls`/`dirname` 报错。
