## 15. 命令陷阱速查（避免误判）

1. `ls -1 _*.log _*.txt _* | wc -l` → **重复计数**；应用 `ls -1 _* | wc -l`。
2. `ls -1 app/api/v1/endpoints/_*.py` → **会匹配 `__init__.py`**；须加 `grep -v __init__`。
3. `grep -c "include_router"` → 含文件头注释；应用 `grep -c "app.include_router("`。
4. `grep -rn "\.delay(\|apply_async("` → 命中 docstring；须排除注释行。
5. 本机 bash 需前缀 `export PATH="/usr/bin:/bin:/usr/local/bin:$PATH"`，否则 `ls`/`dirname` 报错。
6. `grep -c "vitest" .github/workflows/*` → **只统计前端 job**，会漏掉 `ci.yml` 的 `backend-test`（ruff + alembic 校验 + 后端 `pytest --cov-fail-under=80`）。判断 CI 覆盖面**必须逐 job 读 `ci.yml`**，不可凭单一关键词下结论。
7. 按记忆列举 workflow 易写成「3 个」→ 实测 **5 个**，`pr-regression.yml` / `daily-regression.yml` 最易遗漏。应用 `(Get-ChildItem .github/workflows -File).Count`（Windows）或 `ls .github/workflows | wc -l`（bash）。
8. `grep -rn "_verify_project_access"` → 会把**平行实现**（`_history_asset_helpers.py:58`）与 **re-export 别名**（`pipeline_deps.py:22`、`pipeline.py:34`）一并命中，**不能据此判定「已归一」**。判定归一时须三类同时看：定义点 / re-export 点 / 真实调用点。
9. 把「自愈权重 0.4 / 0.4 / 0.2」定位到 `locator_healing_agent.py` → **错**（该文件无权重逻辑）。应用 `grep -rn "_CONF_WEIGHT" app/ --include=*.py` 定位真身；且「三级」在本库有多义（**导航三级降级** / **三级密钥回退**），须看上下文，勿望文生义。
10. Windows PowerShell 下无 `ls -1` / `wc -l`；计数应用 `(Get-ChildItem -Recurse -File -Filter *.py).Count`。另：`$var` 在部分命令封装层会被吞掉，脚本化时优先使用**字面路径**而非变量。
