# M0 基线度量指标定义

> 版本：v1.0 | 制定日期：2026-05-01
> 关联文档：`quality_baseline.md`、`ai_cost_baseline.md`、`iteration-pipeline-plan.md` §7

---

## 1. 文档用途

本文档是 **度量契约**：正式定义每个指标的计算公式、数据来源、采集频率，基线值同时写入作为 M1~M4 各阶段改进效果的对比基准。

**约束规则**：
- 后续里程碑收口任务（M1-T18, M2-T14, M3-T08, M4-T11）必须引用此文档
- 公式变更需通过 ADR 记录，重新采集基线并更新本文档版本号
- 新增指标需补采集历史数据后加入

## 2. 质量基线指标

### 2.1 用例总数

| 项 | 内容 |
|------|------|
| 定义 | 项目中未删除的测试用例数量 |
| 公式 | `COUNT(*) WHERE project_id = ? AND is_deleted = 0` |
| 数据来源 | `test_cases` 表 |
| 采集频率 | 每个里程碑收口时 |
| 基准日期 | 2026-05-01 |
| 基线值 | **1**（测试项目 ID=100417） |
| 预期趋势 | M1~M4 逐步增长，但不应出现爆炸性增长（AI 去重生效） |
| 备注 | 按 project_id 分组统计；含软删除过滤 |

### 2.2 人工评审通过率

| 项 | 内容 |
|------|------|
| 定义 | 已完成人工评审的用例中，评审通过的占比 |
| 公式 | `(review_status = 'approved') / (review_status != 'pending') * 100` |
| 数据来源 | `test_cases.review_status` |
| 采集频率 | 每个里程碑收口时 |
| 基准日期 | 2026-05-01 |
| 基线值 | **N/A**（当前无评审记录） |
| 预期趋势 | 引入 Pipeline 后，AI 先验质量分 ≥ A 的用例自动通过，通过率应上升 |
| 备注 | 审批评审记录不存在时标 N/A，不作为改进度量的强制对比项 |

### 2.3 执行通过率

| 项 | 内容 |
|------|------|
| 定义 | 已完成执行的用例中，状态为 passed 的占比 |
| 公式 | `COUNT(status='passed') / COUNT(*) * 100` |
| 数据来源 | `test_case_executions.status` |
| 采集频率 | 每个里程碑收口时 |
| 基准日期 | 2026-05-01 |
| 基线值 | **N/A**（当前无执行记录） |
| 预期趋势 | Pipeline 生成的用例质量提升 → 执行通过率上升 |
| 备注 | 按 project 聚合；执行次数不足（<3）时置信度低 |

### 2.4 平均步骤数

| 项 | 内容 |
|------|------|
| 定义 | 所有用例的 steps_json 数组长度的算术平均 |
| 公式 | `SUM(LEN(steps_json)) / COUNT(cases_with_steps)` |
| 数据来源 | `test_cases.steps_json` |
| 采集频率 | 每个里程碑收口时 |
| 基准日期 | 2026-05-01 |
| 基线值 | **1.00** 步 |
| 预期趋势 | AI 生成的标准用例应稳定在 3~8 步；过少可能遗漏场景 |
| 备注 | 需处理 JSON 格式兼容（str/list）；NULL 的 case 不计入分母 |

### 2.5 用例修改率

| 项 | 内容 |
|------|------|
| 定义 | 创建后被修改过的用例占比（update_time > create_time） |
| 公式 | `COUNT(update_time > create_time) / COUNT(*) * 100` |
| 数据来源 | `test_cases.create_time`、`test_cases.update_time` |
| 采集频率 | 每个里程碑收口时 |
| 基准日期 | 2026-05-01 |
| 基线值 | **0.0%**（当前仅 1 条用例未修改） |
| 预期趋势 | AI 生成质量越高，手工人为修改越少 → 修改率下降 |
| 备注 | 包含所有类型修改（AI+人工），不区分修改来源 |

### 2.6 相似用例比率

| 项 | 内容 |
|------|------|
| 定义 | 标题文本相似度 ≥ 0.85 的用例对数占总用例数的比例 |
| 公式 | `COUNT(similar_pairs) / total_cases * 100` |
| 数据来源 | `test_cases.title`（Python difflib.SequenceMatcher 计算） |
| 采集频率 | 每个里程碑收口时 |
| 基准日期 | 2026-05-01 |
| 基线值 | **0.0%**（当前仅 1 条用例） |
| 预期趋势 | ForwardScan + HistoryFingerprint 去重生效 → 比率下降 |
| 备注 | 相似度阈值 0.85 可调；O(n²) 复杂度，>5000 用例时考虑降采样 |

## 3. AI 成本基线指标

### 3.1 平均 Token 消耗

| 项 | 内容 |
|------|------|
| 定义 | 每次成功 AI 调用消耗的输入 + 输出 Token 平均值 |
| 公式 | `AVG(prompt_tokens + completion_tokens) WHERE status='success'` |
| 数据来源 | `ai_call_log` 表（Pipeline 框架）、`api_cost_log` 表（旧版日志） |
| 采集频率 | 每个里程碑收口时 |
| 基准日期 | 2026-05-01 |
| 基线值 | **N/A**（当前无 AI 调用记录） |
| 预期趋势 | 缓存命中率提升后单次 Pipeline 总 Token 下降 |
| 备注 | 分模型统计；M0 阶段如无数据，待 M1 Pipeline 跑通后补采 |

### 3.2 平均延迟

| 项 | 内容 |
|------|------|
| 定义 | 每次成功 AI 调用的端到端延迟（毫秒）算术平均及 P50/P95 |
| 公式 | `AVG(latency_ms) WHERE status='success'` |
| 数据来源 | `ai_call_log.latency_ms` |
| 采集频率 | 每个里程碑收口时 |
| 基准日期 | 2026-05-01 |
| 基线值 | **N/A**（当前无 AI 调用记录） |
| 预期趋势 | 缓存命中跳过 AI → P95 大幅下降 |
| 备注 | 百分位数需要 ≥20 个样本才有统计意义 |

### 3.3 平均单次成本

| 项 | 内容 |
|------|------|
| 定义 | 每次成功 AI 调用的费用（USD）平均值 |
| 公式 | `AVG(cost_usd) WHERE status='success'` |
| 数据来源 | `ai_call_log.cost_usd` |
| 采集频率 | 每个里程碑收口时 |
| 基准日期 | 2026-05-01 |
| 基线值 | **N/A**（当前无 AI 调用记录） |
| 预期趋势 | 缓存复用 + fallback 模型降本 → 平均成本下降 |
| 备注 | 成本基于配置 `AI_PRICE_PER_1K_INPUT/OUTPUT` 实时计算 |

| 基准日期 | 2026-05-01 |
| 基线值 | **N/A**（当前无 AI 调用记录） |

| 备注 | 失败含网络超时 / JSON 解析失败 / API 返回错误 |

## 4. 复合质量指标（对齐 plan §7）

### 4.1 先验质量分（Prior Quality Score）

定义见 `iteration-pipeline-plan.md` §7.1：

```
score = 25*signal_prd + 20*signal_testpoints + 25*signal_ui + 15*signal_history + 15*signal_confirmed - min(15, conflicts*3)
```

| 等级 | 分数区间 | 含义 | 自动化策略 |
|------|----------|------|------------|
| A | ≥85 | 信号完整 + 用户确认到位 | 可自动落库（M1 阶段 AUTO_APPROVE_MIN_GRADE='A'） |
| B | 65~84 | 缺一类信号或部分确认 | 需人工评审 |
| C | 45~64 | 多类信号缺失 | 需人工评审 + 补充信号 |
| D | <45 | 严重信号缺失 | **禁止自动落库**，强制人工介入 |

基线值：**N/A**（Pipeline 未运行，无先验分数据）。

### 4.2 后验质量分（Posterior Quality Score）

定义见 `iteration-pipeline-plan.md` §7.2：

```
posterior = 0.5*review_pass_rate + 0.3*execution_pass_rate + 0.2*(1 - modification_rate)
```

| 项 | 内容 |
|------|------|
| 数据来源 | `review_decision` + `test_case_executions` + `test_cases` |
| 采集频率 | 每周定时任务聚合 |
| 最低样本要求 | 执行次数 ≥ 3（配置 `POSTERIOR_MIN_EXECUTIONS`） |
| 基准日期 | 2026-05-01 |
| 基线值 | **N/A**（流水线未运行） |
